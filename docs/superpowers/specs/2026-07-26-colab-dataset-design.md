# Расширенный датасет и обучение в Google Colab

Дата: 2026-07-26
Статус: утверждено, план реализации не написан

## Задача

Собрать датасет заметно больше нынешнего, зафиксировать разбиение на выборки и
перенести обучение в Google Colab, сохранив возможность разбирать результаты
прогонов без ручного копирования логов.

## Ограничения, из которых всё следует

1. **Локальная машина пуста.** Ни `DADS/`, ни `cache_dads/`, ни `cache_hard/`,
   ни `field/*.wav` на диске нет (всё в `.gitignore`), `torch` не установлен,
   GPU нет. Готовить кэш локально бессмысленно: скачать 18 ГБ, собрать 9 ГБ,
   залить 9 ГБ обратно. Препроцессинг идёт там же, где обучение.
2. **Бесплатный Colab (T4, 15 ГБ RAM, ~110 ГБ диска).** Сессия обрывается —
   это норма, а не край случая. Диск после обрыва теряется целиком.
3. **Коннектора к Google Colab не существует** — у Colab нет публичного API
   для запуска ноутбуков. Наблюдать за прогоном напрямую нельзя.

## Архитектура

Приватный dataset-репозиторий Hugging Face `Onikore/airadar-hub` работает
общей шиной между Colab и рабочей сессией.

```
                  ┌──────────────────────────────┐
   prep (1 раз)   │   HF: Onikore/airadar-hub    │
  ───────────────>│   cache/  code/  field/      │
                  │   runs/<имя>/train.log       │<─── чтение через hf_fs cat
   train (N раз)  │   runs/<имя>/last.pt         │
  <──────────────>│   manifest.json              │
                  └──────────────────────────────┘
```

Выбор HF, а не Google Drive: содержимое читается инструментами HF-коннектора,
то есть логи и метрики прогона доступны для разбора сразу после эпохи.

## Источники данных

| источник | что берём | скачать | окон |
|---|---|---|---|
| `geronimobasso/drone-audio-detection-samples` | всё | 6.8 ГБ | ~341k (дрон 164k / фон 177k) |
| `ahlab-drone-project/DroneAudioSet`, конфиг `drone-only` | 168 записей | 3.4 ГБ | ~120k дрона (кэп) |
| `danavery/urbansound8K` | 8732 клипа, поле `class` | 7.0 ГБ | ~35k негативов |
| `ashraq/esc50` | 2000 клипов по 5 с, поле категории | 0.8 ГБ | ~20k негативов |

### Обоснование состава

**DroneAudioSet не является подмножеством DADS** — это независимая запись с
другими машинами и другой основной частотой. Прямо адресует главную дыру
проекта: recall 98.9% на DADS против 0.0% на полевой записи грузового дрона,
потому что в DADS почти всё — малые квадрокоптеры с f0 около 200 Гц.

Кэп ~120k окон, выбранных равномерно по 168 записям: без него 168 записей по
~10 минут дадут 200k+ окон и перевесят DADS.

**Конфиги `source-only` и `drone-with-source` не берём.** Первый — 56 ГБ в
распакованном виде, и его роль (фон) уже закрыта ESC-50 и UrbanSound8K, причём
с категориями, которые нужны для таблицы ложных срабатываний. Второй — готовые
смеси дрона с источником, тогда как `Augment` в `train.py` миксует сам под
заданный SNR; чужие смеси с неизвестным SNR только зашумят обучение.

**ESC-50 и UrbanSound8K берём с HF напрямую, а не через Kaggle
DroneAudioDataset.** Три выигрыша: уходит зависимость от набора, которого нет
на диске; клипы приходят целыми (ESC-50 по 5 с вместо порезанных на сегменты
по 1 с); категория читается из колонки, а не восстанавливается регуляркой из
искалеченного имени файла. Негативов ~55k против нынешних 47k, трудных
категорий примерно втрое больше.

## Разбиение выборок

### Заморозка сплита

Сейчас сплит вычисляется в момент обучения: `GroupShuffleSplit(n_splits=1,
test_size=0.15, random_state=0)` в `train.main` и повторно, теми же
параметрами, в `eval.main`. При четырёх источниках и кэше, живущем на HF,
этого недостаточно — любое изменение порядка данных молча переставит границу,
и два прогона станут несравнимыми.

Сплит вычисляется один раз в `prep_hf.py` и сохраняется массивом `split` в
`meta.npz`. Обучение и оценка его только читают.

### Три части вместо двух

| часть | доля | назначение |
|---|---|---|
| train | 75% | обучение |
| val | 15% | отбор эпохи, подбор гиперпараметров |
| test | 10% | не трогается до финальной проверки |

Сейчас удержанной части нет вообще: `auc_hard` одновременно отбирает чекпоинт
и служит отчётной метрикой, то есть числа, которому можно верить в отчёте, в
проекте нет.

### Группировка

Разбиение идёт по группам, не по окнам. Все три части содержат все четыре
источника.

| источник | ключ группировки | точность |
|---|---|---|
| DADS | блок номеров по 250 (`BLOCK`, как сейчас) | приближение; имена обрезаны, точнее нельзя |
| DroneAudioSet | индекс записи | точная, 168 групп |
| UrbanSound8K | `fsID` исходной записи | точная |
| ESC-50 | номер клипа | точная |

`cache_hard` делится тем же механизмом, а не отдельным делением 50/50 по
порядку окон внутри категории, как сейчас в `load_hard`.

## Формат кэша

Контракт `meta.npz` для `cache_dads`:

| ключ | тип | смысл |
|---|---|---|
| `y` | `int8` | метка 0/1 |
| `group` | `int64` | ключ группировки, пространства источников не пересекаются |
| `src` | `int8` | 0 = DADS, 1 = DroneAudioSet |
| `split` | `int8` | 0 = train, 1 = val, 2 = test |
| `synth` | `bool` | синтетика Griffin-Lim (существующее поле) |
| `n`, `win` | `int64` | размерности `windows.bin` |

Для `cache_hard` — `cat` (строковые категории), `group`, `split`, `n`, `win`,
`hard` (список трудных категорий), как сейчас.

Наличие `src` позволяет считать метрики отдельно по источникам: без этого
нельзя будет увидеть, что модель научилась на DroneAudioSet и просела на DADS.

## Изменения в коде

Существующие контракты `load_cache`, `load_hard`, `load_field` сохраняются,
поэтому `detect.py`, `web.py`, `spectrum.py` и `diag_*.py` правок не требуют.

`load_hard` продолжает возвращать четырёхэлементный кортеж
`(X, cat, train_idx, val_idx)` — вызывающий код в `train.py` и `eval.py` не
меняет форму. Индексы теперь берутся из `split`, а не из деления пополам по
порядку окон. Удержанная часть (`split == 2`) доступна отдельной функцией
`load_hard_test()`, которую до финальной проверки не вызывает никто.

| файл | изменение |
|---|---|
| `prep_hf.py` | новый: четыре источника → кэш + замороженный сплит; стриминг по row-group; устойчив к обрыву (манифест + докачка) |
| `hub.py` | новый: `push(path)` / `pull(path)` к HF-репо, чтобы ноутбуки оставались короткими |
| `train.py` | `load_cache` и `load_hard` читают `split` из meta вместо `GroupShuffleSplit`; флаг `--resume`; лог эпохи дублируется в jsonl |
| `eval.py` | `main` читает `split` вместо повторного `GroupShuffleSplit` (строка 102) |
| `notebooks/01_prep.ipynb` | новый: один прогон, ~1.5–2 ч, кладёт кэш на HF |
| `notebooks/02_train.ipynb` | новый: тянет кэш (~5 мин), учит, пушит лог и чекпоинт каждую эпоху |

`prep_dads.py` и `prep_hard.py` остаются нетронутыми. Если `split` в `meta.npz`
отсутствует (старый кэш), `load_cache` откатывается на `GroupShuffleSplit` с
прежними параметрами — старые кэши продолжают работать.

У всего нового кода — режим `--selfcheck`, как принято в проекте.

## Устойчивость к обрыву сессии

**prep.** Пишет пошардово. После каждого шарда обновляет `manifest.json` на HF
(список обработанных шардов, счётчики окон) и доливает готовую часть
`windows.bin`. Перезапуск читает манифест и продолжает с места обрыва.

**train.** Каждую эпоху пушит `runs/<имя>/last.pt` — веса, состояние
оптимизатора и планировщика, номер эпохи, состояние генераторов случайных
чисел — и дописывает строку в `runs/<имя>/train.log` и `metrics.jsonl`.
Перезапуск с `--resume` подхватывает `last.pt`.

Кэш заливается один раз; каждая последующая сессия обучения стартует за ~5
минут вместо 1.5–2 часов препроцессинга.

## Полевые записи

`field/drone_video*.wav` — единственная ненасыщенная метрика проекта. На диске
их нет, пользователь предоставит. Кладутся в `field/` репозитория HF, ноутбук
скачивает их вместе с кэшем. `load_field()` не меняется; при частоте
дискретизации, отличной от 16 кГц моно, добавляется конвертация на входе.

## Риски

**Квота приватного хранилища HF.** Кэш ~9 ГБ. Проверяется до заливки. Запасной
вариант: `windows.bin` в Google Drive (15 ГБ бесплатно), логи и чекпоинты всё
равно на HF, чтобы оставаться доступными для разбора.

**Лицензии.** UrbanSound8K и ESC-50 — CC BY-NC. Производные окна в приватном
репозитории это допускает. Репозиторий не делается публичным.

**Формат DroneAudioSet не документирован** — частота дискретизации и число
каналов в карточке датасета не указаны. Первая ячейка prep печатает схему и
параметры одной записи до обработки 3.4 ГБ. `to_mono_16k` уже умеет
многоканальный вход и ресемплинг.

**Токен HF.** Только через `userdata.get('HF_TOKEN')` (Colab Secrets). В файлы
репозитория не попадает. Токен, присланный в переписке, подлежит перевыпуску.
