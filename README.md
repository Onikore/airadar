# AirRadar — акустическое обнаружение БПЛА

Пассивное обнаружение дронов по звуку одного микрофона. Целевые условия: лес,
близость ЛЭП, максимальная дальность. Пеленгация (азимут) — отдельная ветка на
GCC-PHAT по 4 каналам, нейросеть в ней не участвует.

Текущий этап: **бинарный детектор «дрон / не дрон» по одному каналу**,
архитектура второго поколения — [DroneNet2](#архитектура). Классификация типа
(FPV / самолёт / промышленный) не реализована — см. раздел «Чего нет».

---

## Зачем всё переписано (2026-07-26)

Первая архитектура (`DroneNet`, лог-мел + свёрточная сеть, история ниже) на
DADS показывала AUC 0.998, а на реальном полевом грузовом дроне —
recall 0.0% при рабочем FAR. Разбор
([docs/superpowers/specs/2026-07-26-architecture-redesign-design.md](docs/superpowers/specs/2026-07-26-architecture-redesign-design.md))
свёл причину к двум фактам, а не к «домен-шифту» как необъяснимой сущности:

1. **Разрешение по частоте ограничено длиной окна анализа, а не `n_fft`.**
   Окно 0.128с физически не может разделить гул ЛЭП 50Гц и гребёнку дрона
   62Гц (12Гц друг от друга) — сколько ни меняй раскладку mel-банка.
2. **На mel-шкале смена f0 — не сдвиг.** Свёртка эквивариантна трансляции;
   перенос знания с лёгких квадрокоптеров (f0≈200Гц) на тяжёлые дроны
   (f0≈60-80Гц) на mel-входе невозможен by design.

Отсюда — переход на **constant-Q (лог-частотная ось, где смена f0 = сдвиг)**,
**harmonic stacking** (гребёнка ищется явно, а не надеждой на то, что сеть её
выучит по текстуре) и контекст 4с с обучаемой агрегацией вместо окна 0.5с и
правила «k из m». Полное обоснование, включая арифметику по каждому пункту —
в самой спецификации.

Собственная история находок старой архитектуры (утечка по частоте
дискретизации, синтетика Griffin-Lim, насыщенные метрики, гул ЛЭП vs гребёнка
дрона — четыре раза подряд метрика показывала 0.99 и врала) сохранена в
[git-истории README](https://github.com/Onikore/airadar/commits/master/README.md)
и в [docs/metrics-plan.md](docs/metrics-plan.md). Не пересказывается здесь
заново — она объясняла проблемы архитектуры, которой больше нет.

## Архитектура

Каноническое описание — спецификация
[docs/superpowers/specs/2026-07-26-architecture-redesign-design.md](docs/superpowers/specs/2026-07-26-architecture-redesign-design.md)
(диагноз, обоснование каждого решения, риски). Здесь — сводка того, что
реально реализовано.

**Признак.** Constant-Q через `nnAudio` (GPU), 40–8000Гц, 24 бина/октаву,
183 бина, шаг 128мс. Плюс `ch1` — каузальный скользящий перцентиль
расширяющимся окном (фон/шум отдельным каналом). Сборка `[ch0,ch1]` —
`airadar/features/frontend.py`.

**Модель `DroneNet2`** (`airadar/models/dronenet2.py`), **529 526**
параметров:

- **Ветка A (гармоническая)** — harmonic stacking на f0-диапазоне 40–800Гц
  (104 бина лог-оси, 8 гармоник чистым индексированием), ищет гребёнку явно.
- **Ветка B (текстурная)** — обычная свёртка по полной CQT-сетке, ловит
  широкополосный лопастной шум малых FPV.
- **Attention-MIL** — клип-логит как обучаемая взвешенная сумма покадровых
  логитов по 32 кадрам (4с контекста). Замена правилу «k из m»: накопление
  обучается, а не подбирается руками.
- **Вспомогательные головы** f0/salience — мультизадачная регуляризация, в
  рантайме не используются.

Верхняя граница f0-поиска поднята с 400 до 800Гц 2026-07-28 (не по плану, по
факту): реальная FPV-запись показала доминанту ~390-400Гц, ровно на старой
границе. Подробности и честная оценка эффекта —
[docs/2026-07-29-f0-extension-findings.md](docs/2026-07-29-f0-extension-findings.md).

Вся конфигурация (`FeatureCfg`/`ModelCfg`/`AugCfg`/`TrainCfg`,
`airadar/config.py`) сериализуется в чекпоинт целиком — инференс не может
разойтись с обучением по параметрам признака.

## Текущее состояние и честные находки

- **RMS-нормализация (2026-07-28).** Систематическая отладка нашла: `val_loss`
  падал, а реальное полевое качество ухудшалось с обучением, потому что
  синтетические позитивы обучающей выборки были систематически ~2x громче
  негативов (утечка громкости как признака класса). Исправлено
  (`airadar/augment/mixing.py:normalize_rms`), эффект измерен:
  auc_fh на полевых записях 0.116→0.930 и 0.005→0.722 на пике. Полный разбор —
  [docs/2026-07-26-local-training-findings.md](docs/2026-07-26-local-training-findings.md).
- **val_loss ненадёжен как критерий отбора чекпоинта.** Формально план
  предполагал SWA последних трёх эпох (§6.3 спецификации); по факту
  используется bench-sweep по каждой сохранённой эпохе на реальных полевых
  записях — val_loss систематически расходится с реальным `auc_fh` (минимум
  val_loss на эпохе 8 против максимума auc_fh на эпохе 14 в одном прогоне).
- **AUC ≠ абсолютная уверенность.** Расширение диапазона f0 до 800Гц заметно
  улучшило AUC-ранжирование на полевых записях, но прямая проверка
  `sigmoid(clip_logit)` показала: ни старая, ни новая модель ни разу не
  переходит порог 0.5 (тот же порог, которым веб-демка красит статус) —
  максимум 16%. Исходная жалоба «FPV-дрон не детектируется в живой демке»
  расширением диапазона f0 не решена. Гипотеза (не проверена):
  `pos_weight=0.171` в лоссе системно занижает уверенность на позитивах;
  либо разрыв между синтетическими тренировочными миксами и реальным сжатым
  звуком. Подробности —
  [docs/2026-07-29-f0-extension-findings.md](docs/2026-07-29-f0-extension-findings.md).
- **Калиброванной рабочей точки (порога решения) пока нет.** Bench-харнесс
  честно об этом сообщает: на текущем корпусе трудных записей недостаточно
  непрерывного фона, чтобы посчитать FA/час — нужен отдельный непрерывный
  фоновый корпус (этап 4 плана, §9 спецификации, не начат).

## Данные

Манифест первого класса (`data/manifest.parquet`) + одно бинарное хранилище
клипов (`data/clips.bin`, гигабайты, не в git — см. `.gitignore`) вместо
разрозненных `cache_dads/`/`cache_hard/` старого пайплайна. Собирается из
четырёх источников HuggingFace (`hf_sources.py`):

| источник | что даёт |
|---|---|
| `geronimobasso/drone-audio-detection-samples` (DADS) | основной корпус дронов, блочная группировка (имена обрезаны) |
| `ahlab-drone-project/DroneAudioSet` | дополнительные записи дронов, точная группировка |
| `danavery/urbansound8K` | негативы с категориями (трудные: engine, drilling, jackhammer...) |
| `ashraq/esc50` | негативы с категориями, включая chainsaw/helicopter/wind/rain |

Сборка: `python cli/build_manifest.py` (часы, IO-связано, чекпоинт по шардам —
безопасно прерывать и продолжать). Аудит целостности —
`python cli/manifest_audit.py`. На момент последней сборки: 191 196 строк,
3555 групп (см. `bench_out/` и вывод аудита для актуальных чисел).

f0-разметка (нужна вспомогательным головам) — отдельный проход
`python cli/label_manifest_f0.py`.

Полевой холдаут (`field/drone_video1.wav` — FPV вблизи, `field/drone_video2.wav`
— тяжёлый одномоторный дрон-крыло издалека) — две реальные YouTube-записи,
единственная небинарная проверка вне синтетики; не в eval-манифесте.

## Структура

```
cli/                     точки входа: build_manifest, train, bench, webdemo,
                          label_manifest_f0, manifest_audit, diag, selfcheck
airadar/                 пакет: features/ models/ train/ augment/ data/ bench/ diag/
docs/superpowers/specs/  архитектурная спецификация (канон)
docs/superpowers/plans/  исполненные планы по этапам (история, не трогать)
docs/                    датированные находки, метрики
evalx/                   разведочные CPU-скрипты старого пайплайна (f0_survey, feat_visibility, field_ci)
field/                   полевые holdout-записи
models/                  чекпоинты (не всё в git — см. ниже)
data/                    manifest.parquet, clips.bin (не в git, гигабайты)
logs/  bench_out/        логи и bench-отчёты прогонов
archive/                 отработавшее: notebooks, старые чекпоинты, plan.md (заменён спецификацией)
```

**Корневые скрипты** (`train.py`, `eval.py`, `detect.py`, `web.py`,
`spectrum.py`, `diag_leak.py`, `diag_hard.py`, `diag_compare.py`, `hub.py`,
`prep_hf.py`) — пайплайн первого поколения (`DroneNet`, мел-спектр). Не
удалены: `hf_sources.py` переиспользуется новым пайплайном, а
`models/dronenet_local.pt` остаётся базовой цифрой для сравнения
(`bench_out/dronenet_local.json`). Активная разработка идёт в `cli/`+`airadar/`.

В git закоммичены только код, документация и единичные показательные
bench-отчёты — не чекпоинты по каждой эпохе и не сырые логи прогонов (гигабайты
бинарников, см. комментарий в `.gitignore` про `data/`). Актуальные локальные
чекпоинты называются по конвенции `<run_name>_true_best.pt` (выбран
bench-sweep'ом, не автовыбором `train.py`).

## Команды

Подробный разбор — [RUNBOOK.md](RUNBOOK.md). Коротко:

```bash
python cli/selfcheck.py                 # вся логика без данных и без GPU, 33+ проверки
python cli/build_manifest.py --limit 1  # сборка манифеста, сначала на пробу
python cli/build_manifest.py            # полная сборка — часы

python cli/train.py --epochs 15 --bs 32 --run-name my_run \
    --save-every-epoch --seed 0 --num-workers 4
python cli/bench.py --model models/my_run_ep014.pt --name my_run_ep014 --arch dronenet2

python cli/webdemo.py --model models/dronenet2_seed0_f0ext_true_best.pt
# -> http://127.0.0.1:5000, живой тест по микрофону или загрузкой файла
```

## Окружение

RTX 4050 Laptop 6ГБ (эта машина обучалась ранее); текущее полноценное
обучение — на локальном GPU. `torch.cuda.is_available()` сам выбирает
`cpu`, если GPU нет — весь код проверяется `--selfcheck` без карты.

Известная узкая точка (не вычисления): случайный доступ к `clips.bin`
(гигабайты) под большим числом эпох упирается в промах кэша страниц ОС —
решается `DataLoader(num_workers>0, persistent_workers=True)`, см.
[docs/2026-07-26-local-training-findings.md](docs/2026-07-26-local-training-findings.md).

## Чего нет

**Классификации типа дрона.** Ни в одном из четырёх источников нет меток
FPV / самолёт / промышленный — только 0/1. Разметку придётся делать самим.

**Пеленгации.** Азимут по GCC-PHAT задуман как отдельная 4-канальная ветка
(упоминается в докстринге `train.py`), но реализации, теста или даже
симуляции в репозитории нет — только идея.

**Калиброванной рабочей точки.** См. «Текущее состояние» выше — нужен
непрерывный фоновый корпус, не собран.

**Полевой проверки за пределами двух YouTube-записей.** Настоящий выезд с
телеметрией не проводился.
